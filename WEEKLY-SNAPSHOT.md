# Model Tides weekly snapshot (v1)

Personal reports and opt-in aggregate contributions use this JSON, compressed with Brotli in transit:

```json
{
  "format": "model-tides-weekly",
  "version": 1,
  "weeks": [
    { "week": "2026-09-28", "models": { "anthropic/claude-sonnet-4": 2, "openai/gpt-5": 1 } }
  ]
}
```

`week` is the Monday UTC date. Each count is the number of observed session starts or model changes to that model in that week, not turns or tokens. The weekly format carries **no** event timestamps, prompts, replies, paths, source names, session IDs, or message IDs. Uploads require `Content-Type: application/vnd.model-tides.weekly+json`, `Content-Encoding: br`, and `X-Model-Tides-Schema: weekly-v1`; new personal reports also require `X-Model-Tides-Report: personal-v1`. The Worker rejects extra fields, invalid weeks, excessive counts, compressed uploads over 64 KiB, and expanded JSON over 512 KiB. It allows up to 520 weeks, 2,048 model-week cells, and 10,000 events in one cell. These limits also apply to the complete stored report after any replacement; older reports above the limits keep their counts and can still be hidden or deleted. The CLI preview shows every model name and count that will be uploaded, including older names absent from current catalogs. The Worker validates each name's length and characters, but cannot verify self-reported model use.

`POST /api/contributions/personal` creates a UUIDv7 ID, a separate private 256-bit owner token, and a personal link that anyone with the URL can view. The new path cannot create an aggregate contribution on an older Worker. Existing `POST /api/contributions/private` clients retain their original private-report/aggregate contract until upgraded; the oldest `POST /api/contributions` path returns 426. New personal reports start outside the aggregate. `POST /api/contributions/:id/contribute` adds all stored counts to the aggregate after owner review and `X-Model-Tides-Reviewed-Revision`; `/withdraw` removes them without deleting the personal link. Historical aggregate reports remain opted in by migration default; new personal reports start opted out. Both operations require `Authorization: Bearer <token>`; withdrawal advances the revision so a delayed consented contribution cannot undo it. `POST /api/contributions/:id/share` publishes a hidden personal report; `/unshare` hides it again without changing aggregate participation. `GET /api/contributions/:id`, `/u/:id`, and `/og/:id.png` return 404 while a report is hidden; authenticated owners can read their counts. `PUT /api/contributions/:id` replaces named weeks without adding duplicate counts and preserves current visibility and aggregate choice. `DELETE /api/contributions/:id` removes all counts; `/rotate` rotates the key. The Worker stores only a SHA-256 hash of the token. `GET /api/aggregate` and `/og/global.png` count only opted-in contributors and hide model-week cells below five IDs. IDs do not prove distinct people.

The owner also sends `X-Model-Tides-Expected-Visibility: private` or `public` and `X-Model-Tides-Expected-Aggregate: included` or `excluded` on replacement. The Worker checks both when writing; if another session changed either state after consent, replacement returns 409 without changing any counts. Old replacement clients without these headers receive 426. A `modeltides.dev/gist#<owner>/<id>` page uses the same weekly schema but loads the unlisted `model-tides-weekly.json` directly from GitHub in the browser. The fragment hides the gist address from Model Tides requests; GitHub still sees it. Gist counts do not enter the aggregate unless the owner separately uploads and opts in.

Before sharing a hidden report or opting in to the aggregate, owners read and review **all** saved week/model/count pairs, including retained older weeks. Authenticated reads include `revision`, which increases after replacement, share, hide, aggregate opt-in, or withdrawal. `share` and `contribute` require `X-Model-Tides-Reviewed-Revision: <revision>` and atomically reject a changed report with 409. Missing or malformed revisions receive 426; hiding and withdrawing need no revision but invalidate earlier reviews. Owner reads show up to 8,192 stored cells so owners can review older, larger reports. Beyond that, the API returns a bounded owner summary: the key still works for hiding, withdrawing, or deleting, but the report cannot be shared or added to the aggregate without a complete review. Migration `0003_counts_revision.sql` adds the revision; migration `0004_personal_reports.sql` adds aggregate participation with default 1 for existing contributors.

The [local metadata format](MODEL-TIDES.md) contains exact event timestamps and is meant for private transfer. It is never an upload format. The CLI derives weekly snapshots locally and asks for explicit consent before uploading them. The optional `model-tides gist` command sends only the same reviewed weekly JSON to an unlisted GitHub gist after separate consent; unlisted gists are readable by anyone with the URL and retain revisions.
