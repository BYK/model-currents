# Model Tides CLI

Run `npx model-tides@latest upload` to discover local OpenCode, Codex, and Claude Code history, review the exact weekly model counts, and choose whether to contribute them to the community aggregate. New personal reports start private; replacing weeks in an already public report makes the reviewed counts public immediately. Python 3 is needed for the local converters; old compressed Codex rollouts also need `zstd`.

To see your history without sharing it, run `npx model-tides@latest export --output model-tides.json`, then open the file at [modeltides.dev/local/](https://modeltides.dev/local/). Export works offline and never overwrites an existing file. The JSON contains exact event timestamps; keep it private.

Nothing is uploaded until you type `YES`. The CLI sends Brotli-compressed week/model/count pairs; it never sends prompts, responses, exact event times, paths, session IDs, message IDs, or the source databases. Review the model names in the preview: historical names and provider-specific aliases are uploaded exactly as shown. Your contribution uses a separate local private key, kept under `~/.config/model-tides/` (or `XDG_CONFIG_HOME`).

After uploading, run `npx model-tides@latest share` and type `YES` to publish your personal report. Run `unshare` to hide it again without withdrawing your aggregate counts. `link` prints the report address without scanning or contacting the site; it works only while shared. Links created before private uploads remain public until their owners hide them. The homepage displays a model-week only after five contributors upload that model and week; a shared personal report shows your own counts immediately. `gist` asks for separate consent, creates an unlisted gist of weekly counts, and prints a `modeltides.dev/gist#<owner>/<id>` viewer URL. The viewer fetches the gist from GitHub in the browser; Model Tides receives neither the gist address nor its file.

Before `share` asks for `YES`, it shows every stored week, including weeks retained from earlier uploads. The Worker rejects sharing if counts change after review.

To use an exported metadata JSON, run `npx model-tides@latest upload --input model-tides.json`. Run `upload --rotate` or `upload --delete` to manage the key or delete all contributed counts. If you prefer a GitHub link for just the weekly counts, run `npx model-tides@latest gist [--input model-tides.json]` with an authenticated `gh` CLI. After a separate `YES`, it creates an unlisted gist: anyone with the URL can read it, and GitHub keeps previous revisions. It never includes exact event timestamps. See [the project documentation](https://github.com/BYK/model-tides#share-a-weekly-snapshot-optional) for details.
